Die 4 Skills
🔍
Skill 01
Discovery
/ discovery

Scannt die gesamte Codebase nach Design-Mustern. Extrahiert Farben, Abstände, Typografie und Radien aus CSS-Variablen, Inline-Styles und Theme-Dateien — kompiliert alles in eine einzige theme.json als Source of Truth.

Analysiert :root { } CSS-Variablen, TypeScript Theme-Dateien und Inline-Styles
Validiert jeden Token vor dem Schreiben — Fehler bei ungültigen CSS-Werten
Semantische Benennung: colors.surface.high, spacing.xl, radius.pill
theme.json Token Extraction Validation
Zuerst ausführen
📋
Skill 02
Manager
/ manager

Zerlegt eine UI in eine Atomic Design Roadmap — Atoms, Molecules, Organisms, Templates. Verwaltet den Build-State und blockiert Molecules, bis alle zugehörigen Atoms fertig sind. Verhindert Redundanzen in der Zwischenarbeit.

Gate-System: Molecule kann erst starten wenn alle Atom-Abhängigkeiten completed sind
Cross-referenziert Tokens gegen theme.json — Fehler bei unbekannten Tokens
Persistiert Zustand in .claude/cdd-state.json
Atomic Design Gate System cdd-state.json
Nach Discovery
⚡
Skill 03
Worker
/ worker

Konvertiert rohes HTML in produktionsreifen React- oder React-Native-Code. Folgt dem Plan → Validate → Execute Muster strikt — kein Code wird geschrieben, bevor der Plan gegen theme.json und cdd-state.json validiert ist.

Automatische RN-Konvertierungen: flex-direction: row, marginVertical/Horizontal, elevation
Erkennt und flaggt alle ungültigen RN-Properties vor der Ausführung
Schreibt Datei erst nach erfolgreicher Plan-Validierung — Source of Truth bleibt sauber
Plan-Validate-Execute HTML→RN StyleSheet
Pro Atom/Molecule

Skill 04
Storybook Gen
/ storybook-gen

Analysiert Komponenten-Metadaten (Props Interface, Varianten, Types) und generiert vollständige CSF3-Story-Dateien. Kein manuelles Anfassen des Story-Codes mehr nötig.

Generiert: Title, Meta-Object (default args), Story-Objects pro Variant, Decorators
Decorators verhindern Crashes: Wrapping mit NavigationContainer, Theme-Provider, RN-View
Union-Types → Select Controls, Booleans → Toggle, Functions → Action-Logger
CSF3 ArgTypes Decorators
Nach Worker
Progressive Disclosure

Context bleibt sauber.
Tokens bleiben da.

Kein Agent lädt den gesamten Skill-Code in den Speicher. Jeder Skill wird in 3 Stufen geladen — nur was gerade gebraucht wird kommt rein. Das Agent läuft nicht gegen das Token-Limit.

1
Trigger — Name & Beschreibung
Agent sieht nur den Skill-Namen und eine kurze Beschreibung. Entscheidet ob relevant.
~50 tokens
2
Instruktionen laden
Nur wenn der Skill ausgelöst wird, lädt der Agent die vollständigen Anweisungen.
~500 tokens
3
Externe Referenzdateien
Mappings, theme.json, cdd-state.json — nur on-demand gelesen, nie komplett im Speicher.
on-demand
theme.json — colors
colors.bg #0e0e08

colors.tertiary #99f1f3

Nicht nach Kopf nachbauen

Statt eine Burg aus dem Gedächtnis zu rekonstruieren, zerlegst du sie in Steine. Atomic Design zwingt jeden Agenten, nur seinen Teil zu sehen.

🎯

Begrenztes Sichtfeld

Jeder Agent fokussiert sich nur auf seinen Task. Kein Agent versucht, die gesamte App zu verstehen — Context bleibt sauber.

🏗

Zero Trust Architecture

Skills werden auf Schadcode geprüft. Agent weigert sich, nicht verifizierten Code auszuführen. Sicherheit by Default.

⚙

Fabrik, nicht Produkt

Du baust das System, das das System baut. Infrastruktur ist das wichtigste — danach laufen alle Komponenten automatisch.

🔗

Source of Truth

theme.json und cdd-state.json sind unveränderliche Referenzen. Kein Token wird benutzt, der nicht existiert.
